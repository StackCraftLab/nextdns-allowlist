# NextDNS Allowlist Manager

A small, hardened web app that lets a logged-in administrator **add** a hostname
to the allowlist of one NextDNS profile (`59b6c8`) and **view** (read-only, searchable)
the current allowlist. It can't delete,
edit or replace entries, or touch any other NextDNS setting.
See [SECURITY.md](SECURITY.md) for the design, and especially for the **API-key
limitation**: NextDNS keys are account-wide, so the add-only rule is enforced by
this app, not by the key.

```
Browser ──HTTPS──▶ Reverse proxy (Caddy / Nginx / Traefik) ──HTTP──▶ app container :8000
                                                                     │  FastAPI + Jinja2
                                                                     │  SQLite in /data (admin hash, sessions, recent adds)
                                                                     └──HTTPS──▶ api.nextdns.io/profiles/59b6c8/allowlist
                                                                                 (GET to check/list, POST to add — nothing else)
```

## Requirements

* Docker Engine with the **Compose v2 plugin** (`docker compose version`).
  The old Python `docker-compose` 1.x doesn't work on Python 3.12.
* A domain name pointing at the server, so you can serve the app over HTTPS.
* Your NextDNS API key (bottom of <https://my.nextdns.io/account>). Ideally use a
  dedicated NextDNS account that owns only this profile (see SECURITY.md).

## Deploy on Render.com

Render builds the `Dockerfile` straight from your GitHub repo, provides HTTPS
on `https://<name>.onrender.com`, and redeploys on every `git push`. `render.yaml`
is a ready-made Blueprint.

1. **Generate your password hash locally.** The free plan has no persistent disk
   and no shell, so the admin password is supplied as an Argon2id hash, never as
   plaintext:
   ```bash
   docker run --rm -it nextdns-allowlist:latest python -m app.manage hash-password
   ```
   Copy the single `$argon2id$...` line it prints.
2. In Render: **New → Blueprint**, connect your GitHub repo, and select it.
   Render reads `render.yaml` and prompts for two secrets:
   * `NEXTDNS_API_KEY`: your NextDNS API key
   * `APP_ADMIN_PASSWORD_HASH`: the hash from step 1

   `APP_SECRET_KEY` is generated by Render automatically.
3. Click **Apply**. When the deploy is live, open the `.onrender.com` URL and log in as `admin`.

Notes for Render:
* To change the password, generate a new hash and replace `APP_ADMIN_PASSWORD_HASH`
  under **Environment** (Render redeploys automatically).
* The free plan sleeps after ~15 minutes idle (the first request then takes ~1 minute)
  and has no persistent disk. After a sleep or redeploy you have to log in again, and
  the "Recent submissions" list and login-lockout counters are reset. Your NextDNS
  allowlist is unaffected. For persistence, use a paid plan with a disk mounted at `/data`.
* `FORWARDED_ALLOW_IPS=*` is set because the container is only reachable through
  Render's proxy, which supplies the real client IP.
* For a custom domain, add it in Render and set `APP_ALLOWED_HOSTS=<domain>,<name>.onrender.com`.

## Self-hosting with Docker Compose

## 1. Configure secrets

```bash
cp .env.example .env
chmod 600 .env
# Generate the session secret and put it in .env as APP_SECRET_KEY:
openssl rand -hex 32
# Then edit .env: set NEXTDNS_API_KEY, APP_SECRET_KEY, APP_ALLOWED_HOSTS (your domain).
```

`.env` is excluded from git (`.gitignore`) and from the image build context
(`.dockerignore`). Secrets are only injected at runtime, never at build time.

**Docker secrets alternative:** put the key and secret in `secrets/nextdns_api_key`
and `secrets/app_secret_key` (`chmod 600`), remove them from `.env`, and
uncomment the `secrets` sections in `compose.yaml`. Every secret variable also
accepts a `*_FILE` variant.

## 2. Build and start

```bash
docker compose build
docker compose up -d
docker compose ps          # wait for "(healthy)"
```

## 3. Set the administrator password (one-time)

There are no default credentials. Until you run this, every login fails:

```bash
docker compose exec app python -m app.manage set-password
```

You're prompted twice and the input isn't echoed. The password must be at least 12
characters. It's stored only as an Argon2id hash in the `app-data` volume. Run the
same command again to change it; this also logs out every session.
`docker compose exec app python -m app.manage revoke-sessions` logs everyone out.

## 4. Put HTTPS in front (required)

The container only listens on `127.0.0.1:8000`, and production mode sets
`Secure` cookies that browsers won't send over plain HTTP. Pick one option:

**Bundled Caddy (easiest; automatic Let's Encrypt):**
```bash
echo "APP_DOMAIN=allowlist.example.com" >> .env   # also set APP_ALLOWED_HOSTS to the same value
docker compose --profile caddy up -d
```
Ports 80 and 443 must be reachable from the internet for certificate issuance.

**Nginx on the host:** see `deploy/nginx.conf`.
**Traefik:** see `deploy/traefik-labels.example.yaml`.

`FORWARDED_ALLOW_IPS` in `compose.yaml` lists the only proxy addresses trusted to
send `X-Forwarded-For`, which login rate limiting depends on. It already covers a
proxy on the host and the bundled Caddy. Add your proxy's address if it runs elsewhere.

## 5. Verify once with your real key

Log in, then add a harmless hostname you actually want allowed. Check that it
appears under *Allowlist* in the NextDNS dashboard. Submitting it again should report
"already on the allowlist". The successful-add path is covered by mocked tests but
can't be verified live without your key.

## Operations

| Task | Command |
|---|---|
| Logs | `docker compose logs -f app` |
| Stop | `docker compose down` (data volume kept) |
| Update code/deps | `git pull && docker compose build --pull && docker compose up -d` |
| Rotate API key | edit `.env`, then `docker compose up -d` |
| Back up data | `docker compose cp app:/data/app.db ./app-backup.db` (contains the password hash; protect it) |
| Remove everything incl. data | `docker compose down -v` |

## Local development and tests

The tests mock NextDNS and don't need a real API key.

```bash
python3 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements.txt -r requirements-dev.txt
.venv/bin/python -m pytest
```

To run locally over plain HTTP, set `APP_ENV=development` (non-secure cookies)
and `APP_DATABASE_PATH=./dev.db`, then:
`.venv/bin/uvicorn app.main:create_app --factory --reload`.

Dependencies are pinned with hashes. To update them, edit `requirements*.in` and run
`uv pip compile requirements.in --generate-hashes --python-version 3.12 -o requirements.txt`
(and the same for `requirements-dev.in`).

## Configuration reference

| Variable | Required | Description |
|---|---|---|
| `NEXTDNS_PROFILE_ID` | yes | Profile to add to (`59b6c8`). |
| `NEXTDNS_API_KEY` / `_FILE` | yes | NextDNS API key. Server-side only. |
| `APP_USERNAME` | yes | Admin login name. |
| `APP_SECRET_KEY` / `_FILE` | yes | ≥32 random characters; keys session/CSRF token hashes. Changing it logs everyone out. |
| `APP_ENV` | no | `production` (default; forces Secure cookies) or `development`. |
| `APP_ALLOWED_HOSTS` | recommended | Comma-separated `Host` values to accept. Defaults to `RENDER_EXTERNAL_HOSTNAME` on Render, otherwise any. |
| `APP_SESSION_IDLE_MINUTES` | no | Default 30. |
| `APP_SESSION_ABSOLUTE_HOURS` | no | Default 12. |
| `APP_DATABASE_PATH` | no | Default `/data/app.db`. |
| `APP_ADMIN_PASSWORD_HASH` / `_FILE` | no | Argon2id hash from `manage hash-password`; overrides the DB password. Used on Render. In a Compose `.env`, write each `$` as `$$`. |
| `PORT` | no | Listen port, default 8000 (set automatically by Render). |
| `FORWARDED_ALLOW_IPS` | no | Proxy IPs trusted for `X-Forwarded-For` (set in `compose.yaml` / `render.yaml`). |

## Project layout

```
app/main.py        routes (incl. read-only /allowlist view), sessions, CSRF, security headers
app/nextdns.py     add-only NextDNS client (GET to list/check + POST to add, one fixed URL)
app/hostname.py    hostname validation and normalisation
app/security.py    Argon2id, token hashing, rate limiter
app/db.py          SQLite storage
app/manage.py      admin CLI (set-password, revoke-sessions)
app/templates/     Jinja2 templates (no JavaScript)
tests/             pytest suite with a mocked NextDNS API
deploy/            Caddy / Nginx / Traefik examples
```
